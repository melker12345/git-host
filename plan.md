# LocalGitHub - Plan

## Goal

Personal device as a private git hosting endpoint with controlled external sharing.

## Overview

GitHub is a CRUD interface on top of git's object storage. By stripping away
the web UI and social layers, we can create a lightweight alternative that
gives developers true ownership of their code. The app runs on your phone
or laptop and serves repositories over SSH. Access is controlled through
whitelisted SSH public keys or time-limited codes for temporary sharing.
The service defaults to LAN-only — no open ports by default, opt-in only
for external access.

For public repos or large audiences, use GitHub. This is for personal
projects, experiments, and sharing with friends/coworkers.

**Two implementations, one product:**
- **Android app** (Kotlin) — host from your phone
- **PC/laptop binary** (Go) — host from your desktop or server

Both behave identically from the client's perspective.

## Access Model

```
┌─────────────────────────────────────────────────────────┐
│                    Device Owner                         │
│                                                         │
│  ┌─────────────┐    ┌──────────────────────────────┐    │
│  │ Whitelist   │    │  External Access Toggle      │    │
│  │ (SSH Keys)  │    │  ┌────────────────────────┐  │    │
│  │ - laptop    │    │  │ 6-digit pairing code   │  │    │
│  │ - tablet    │    │  │ ECDH-authenticated     │  │    │
│  │ - desktop   │    │  └────────────────────────┘  │    │
│  └─────────────┘    └──────────────────────────────┘    │
└─────────────────────────────────────────────────────────┘
          │                              │
          │ permanent                    │ temporary
          ▼                              ▼
    ┌─────────────┐                  ┌────────────────────┐
    │ My Devices  │                  │ Friends/Coworkers  │
    │ (always)    │                  │ (time-limited)     │
    └─────────────┘                  └────────────────────┘
```

### My Devices (whitelist mode)

- Pre-approved SSH public keys
- Always-on access
- Push/pull without time limits

### External Sharing (pairing mode)

1. Owner taps "Add External Device" → a **6-digit pairing code** appears on screen
2. Code is derived from an ephemeral X25519 public key generated by the host
3. Friend enters the code into their client: `git-host join <CODE>` (or in app)
4. ECDH handshake uses the code to authenticate the channel — no MITM possible without knowing the code
5. Over the secured channel, friend's client sends their Ed25519 SSH public key to the host
6. Host shows: "Allow this device? Fingerprint: [xx:xx:xx...]" — owner approves or denies
7. On approval: key written to whitelist with optional expiry (e.g., 30 days or permanent)
8. Friend now uses standard SSH for all git operations — pairing channel is closed and discarded

## Security

### Ongoing SSH auth

- All git operations (push/pull/clone) go over standard SSH
- Authenticated by Ed25519 pubkey against the whitelist
- SSH transport handles all encryption — no custom crypto needed here

### Pairing channel (ECDH)

Used only during the one-time "Add External Device" flow:

1. Host generates ephemeral X25519 keypair
2. Derives 6-digit PIN: `floor(SHA256(pubkey)[0:3] as uint) % 1_000_000`, zero-padded
3. Listens on pairing port (base port + 1, default 2223)
4. Friend connects and sends their own ephemeral X25519 pubkey
5. Both perform X25519 → `shared_secret`
6. Session key: `HKDF(shared_secret, "localgithub-pairing")`
7. MITM check: host re-derives PIN from `SHA256(shared_secret)` and verifies it matches — if not, abort silently
8. Friend sends their Ed25519 SSH pubkey encrypted with the session key
9. Host shows fingerprint → owner approves → key written to whitelist

MITM is prevented because the attacker cannot know the 6-digit PIN without being physically present to see the host's screen.

### Revocation & Rotation

- Settings: per-key removal from whitelist
- Settings: per-key expiry (optional — set at approval time)
- Expired keys are rejected and logged, not silently dropped

### Principle: Not every device is a hosting endpoint

- Opt-in service, not a default
- No open ports by default
- LAN-only by default

## Device Discovery

Clients need to find the host on LAN without knowing its IP address.

- Host advertises itself via **mDNS** as `_localgithub._tcp.local`
- Devices resolve `hostname.local` automatically (no manual IP config)
- Android: `NsdManager` (built into Android SDK, no library needed)
- PC/Go: `grandcat/zeroconf` library
- Clone URL format: `ssh://git@hostname.local:2222/repo.git`
- SSH config alias (app displays this for copy-paste):
  ```
  Host hostname.local
    HostName hostname.local
    Port 2222
    User git
  ```
  After adding this, users can clone with: `git clone git@hostname.local:repo.git`

---

## Port Strategy

Android (and PC in non-privileged mode) cannot bind to ports < 1024 without root.

- **Default port: 2222** — no root required on any platform
- Configurable in settings if user wants a different port
- PC: optionally bind to 22 if started with sufficient privileges (systemd service)
- App UI displays the SSH config snippet above for first-time setup
- All internal clone URLs shown in the app already include the correct port

## Architecture

### Storage

The host stores bare git repositories on disk.

```
<base_dir>/          # default: ~/repos/ — configurable in settings
├── project1.git     # bare repo
├── project2.git
└── project3.git
```

- All repos are **bare** (no working tree, just git object storage)
- `base_dir` is configurable — users may want repos on an external drive or a custom path
- Default: `~/repos/` on both Android and PC

### Mobile UI

```
┌─────────────────────────────────────┐
│            Repositories             │
├─────────────────────────────────────┤
│                                     │
│   ├── project1.git                  │
│   ├── project2.git                  │
│   └── project3.git                  │
│                                     │
├─────────────────────────────────────┤
│  [Devices]  [Settings]  [+ Device]  │
└─────────────────────────────────────┘
```

- Tapping a repo shows its clone URL and recent push/pull activity
- `[+ Device]` button opens the "Add External Device" pairing flow

### Repo Creation

- Repos are **not** pre-created. They are auto-initialized on first push.
- When `git-receive-pack` is called for a path that doesn't exist, the server runs `git init --bare` at that path before proceeding.
- `git-upload-pack` (clone/fetch) against a non-existent path returns an error: `repository not found`.
- A "New Repo" button in the UI (future) will be a convenience wrapper around the same init — not a different path.

### Path Resolution

When an SSH exec command arrives (e.g., `git-upload-pack '/myproject.git'`):

1. Strip leading `/` from the requested path
2. Reject any path containing `..` or absolute segments outside base dir
3. Resolve against `base_dir`: `<base_dir>/myproject.git`
4. Proceed with the resolved absolute path

Example with default config:
```
git clone ssh://git@melkers-phone.local:2222/myproject.git
  → resolves to ~/repos/myproject.git
```

### Conflict Resolution

- GitHub-style: fast-forward or merge, reject if ambiguous
- Let git handle it natively

### Audit Log

- Host device: view access history (who, what, when)
- Accessible from Settings

### Notifications

- Toggleable in settings
- Alert on push/pull activity
- Alert on new connection

### Backup

- Settings tab: select "backup device" (any connected device)
- Manual: "Sync Now" button
- Auto-sync: on connection open, verify data synced before close
- Syncs all repos to backup device

## Tech Stack

| Platform | Lang   | Role                                |
|----------|--------|-------------------------------------|
| Android  | Kotlin | UI, foreground service, SSH server, git server |
| PC/laptop | Go    | Single-binary server + CLI          |

### Android (Kotlin)

| Component | Library | Notes |
|-----------|---------|-------|
| SSH server | Apache MINA SSHD | Pure Java, production-grade, no JNI |
| Git protocol | JGit | Pure Java git implementation — same stack as Gerrit (hosts AOSP) |
| Device discovery | `NsdManager` | Built into Android SDK |
| QR scanning | ML Kit Barcode | or ZXing |

**Why JGit:** JGit implements `UploadPack` (fetch/clone) and `ReceivePack` (push) — the full server-side git smart protocol — in pure Java. No native binary to bundle, no JNI. Google's Gerrit runs this at scale for the entire Android Open Source Project.

### PC / Laptop (Go)

| Component | Library | Notes |
|-----------|---------|-------|
| SSH server | `gliderlabs/ssh` | Idiomatic Go, minimal boilerplate |
| Git protocol | System `git` binary | SSH exec handler pipes `git-upload-pack` / `git-receive-pack` stdio directly |
| Device discovery | `grandcat/zeroconf` | mDNS via Go |
| Single binary | Go stdlib | `go build` produces one deployable binary |

**Why system git on PC:** When an SSH channel runs `git-upload-pack /path/to/repo`, the handler execs the installed `git` binary and pipes stdin/stdout/stderr. Zero protocol reimplementation, battle-tested, always correct.

### Shared principles
- **Simple**: no custom protocol, no reinvented wheels
- **Fast**: SSH transport, native git pack protocol
- **Reliable**: delegate to proven implementations (JGit, system git)

## Behavior Contract

Both implementations (Go binary and Android app) must behave identically from the client's perspective. This section is the source of truth.

### SSH server
- Listen on port 2222 by default (configurable)
- Authenticate by Ed25519 pubkey — reject if not in whitelist or if expired
- Accept exec requests for `git-upload-pack` and `git-receive-pack` only
- Reject all other exec commands with a clear error message
- Log every connection attempt (accepted and rejected) with timestamp, key fingerprint, and command

### Path resolution
- Strip leading `/` from requested path
- Reject paths containing `..` or any segment that escapes `base_dir`
- Resolve: `<base_dir>/<path>`
- `base_dir` defaults to `~/repos/` — configurable per instance

### Repo lifecycle
- `git-receive-pack` on a non-existent path: `git init --bare <path>`, then proceed
- `git-upload-pack` on a non-existent path: reject with `repository not found`
- No other implicit side effects

### Pairing protocol
- Host listens on `base_port + 1` (default 2223) during an active pairing session only
- Pairing session is triggered manually by owner — never auto-started
- Session expires after 5 minutes if no connection arrives
- Only one pairing session active at a time
- Protocol steps: X25519 exchange → HKDF session key → MITM check (PIN re-derivation) → receive pubkey → owner approval → write to whitelist
- If MITM check fails: close connection, log attempt, do not show approval dialog

### Whitelist format
Flat file (or embedded key-value store), one entry per line:
```
<base64-pubkey> <label> [expiry-unix-timestamp]
```
- Label is set by owner at approval time (e.g., "Alice's laptop")
- Expiry is optional; if absent, key is permanent
- Expired entries are kept in the file but rejected at auth time (for audit purposes)

### mDNS advertisement
- Service type: `_localgithub._tcp`
- TXT records: `version=1`, `port=<port>`
- Advertised hostname: device hostname (e.g., `melkers-phone.local`)
- Stop advertising when service is stopped

## CLI Usage (conceptual)

```bash
# Start the server
git-host serve

# Key management
git-host keys add <pubkey-file> --label "Alice's laptop"
git-host keys list
git-host keys remove <fingerprint>

# Pair a new external device (owner side — generates 6-digit code)
git-host pair
# Output: Pairing code: 482 951  (expires in 5 minutes)

# Join from friend's machine (enters the code, sends SSH pubkey)
git-host join <CODE> --host melkers-phone.local
# Sends ~/.ssh/id_ed25519.pub to host over ECDH-secured channel
# Owner sees fingerprint prompt and approves

# Normal git usage after pairing
git clone ssh://git@melkers-phone.local:2222/myproject.git
git push
git pull
```

## Adding a New Device (Developer Setup Guide)

This is the manual workflow until the in-app pairing flow (Phase 2, item 8) is complete.

### 1. Generate a dedicated SSH key for this device

Never use a personal key. Generate one per machine that needs access:

```bash
ssh-keygen -t ecdsa -b 256 -f ~/.ssh/githost_<machine-name> -N "" -C "githost-<machine-name>"
```

Store it outside `/tmp` so it survives reboots. The project keeps a dev key at
`.githost_dev_key` (gitignored) as a convenience.

### 2. Find the phone's IP address

Either check the phone's Wi-Fi settings or run:

```bash
adb shell ip addr show wlan0 | grep "inet "
```

The SSH server listens on port **2222**.

### 3. Register the public key on the phone

The phone's whitelist lives at (app private storage, requires `adb`):

```
/data/user/0/com.localgithub.githost/files/config/whitelist
```

Format per line: `<base64-encoded-wire-pubkey> <label> [expiry-unix-timestamp]`

The base64 blob is **not** the raw OpenSSH blob — MINA SSHD wraps it with a
4-byte big-endian length prefix. Compute it:

```bash
python3 -c "
import base64, struct, subprocess
blob_b64 = open('~/.ssh/githost_<machine-name>.pub').read().split()[1]
wire = base64.b64decode(blob_b64)
entry = base64.b64encode(struct.pack('>I', len(wire)) + wire).decode()
print(entry + ' <label>')
" | adb shell "run-as com.localgithub.githost tee -a files/config/whitelist"
```

Or replace the whole whitelist (first device, clean slate):

```bash
python3 -c "
import base64, struct
wire = base64.b64decode('<blob-from-pub-file>')
print(base64.b64encode(struct.pack('>I', len(wire)) + wire).decode() + ' <label>')
" | adb shell "run-as com.localgithub.githost tee files/config/whitelist"
```

### 4. Add an SSH config alias (do this once per machine)

Append to `~/.ssh/config`:

```
Host phone-githost
    HostName <phone-ip>
    Port 2222
    User git
    IdentityFile ~/.ssh/githost_<machine-name>
    IdentitiesOnly yes
    StrictHostKeyChecking accept-new
```

After this, all git operations use the alias — no key flags needed.

### 5. Add the git remote to a repo

```bash
# New repo — push for the first time (auto-inits a bare repo on the phone)
cd /path/to/my-project
git remote add phone "ssh://phone-githost/<repo-name>.git"
git push phone main

# Clone an existing repo from the phone
git clone "ssh://phone-githost/<repo-name>.git"
```

### 6. Daily use

```bash
git push phone main        # push
git pull phone main        # pull
git clone ssh://phone-githost/<repo>.git   # clone
```

No `GIT_SSH_COMMAND` prefix needed — the SSH config alias handles key selection.

### Notes

- **IP changes:** If the phone's IP changes (DHCP), update `HostName` in `~/.ssh/config`.
  Long-term fix: use the mDNS hostname (`<device>.local`) once mDNS is wired into the Android app.
- **Proper pairing:** The above is the manual bootstrap. Once Phase 2 pairing is
  complete, the app will handle key exchange and whitelist registration automatically.
- **Key type:** Use `ecdsa` (P-256) or `rsa`. Ed25519 auth is not yet working on
  Android because MINA SSHD's EdDSA registrar is disabled (it conflicts with Android JCE).
- **Clone from phone not yet working** — tracked as next item.
